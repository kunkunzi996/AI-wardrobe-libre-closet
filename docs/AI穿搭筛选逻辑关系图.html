AI 穿搭筛选逻辑

准备 设计有、代码跳过 AI 组套 后核 已废除的本地兜底 给你看的结果

一、整条路线

1. 你点「生成搭配」

输入一句话（例如明天上班穿什么）+ 天气（自动定位 / 手动城市 / 这次没温度）。不管雨、风、湿度。

2. 只拿你这个微信号的衣橱

按登录用户隔离。衣橱是空的 → 直接 0 套，结束。衣橱里的衣服都能进名单，不再区分待洗、收纳。

3. 定核心衣服

你从某件点「围绕这件」→ 核心就是那件，三套都得带着它。
没指定 → 这次没有核心，不拿最新一件锁死三套。

4. 先筛候选衣橱

本地规则硬筛：天气冷热、你明确说的颜色/厚薄、不要裙子（不含裤子）/不要外套。没标颜色却说只要黑色 → 丢掉。核心自己不丢，但和需求打架必须提醒。
筛完没衣服 → 0 套，不硬凑。剩下的才叫候选衣橱。

5. AI 组套并写理由

模型只能用候选衣橱里的真实 ID。有核心才必须带上；没核心则不必共用一件。最多 3 套。两套是否相同只看衣服 ID 集合，不看标签。

AI 交回来之后分两条路

6a. AI 至少交回 1 套 → 后核

  1. 假 ID / 别人的衣服 → 丢掉
  2. 同一套里同一件出现两次 → 留一次
  3. 指定了核心却没带上 → 强制加回去
  4. 非核心再拦冷热、硬性需求、排除品类
  5. 整套衣服 ID 完全相同 → 只留一套
  6. 最多留 3 套
  7. 补需求冲突提醒、温度提醒、同色/撞色那句话

不核：两条裙子能不能配、三套像不像、理由乱不乱。

6b. AI 失败或 0 套 → 不搭配

  1. 不再用本地 A/B/C 硬凑
  2. 直接 0 套给你看

7. 给你看

6a 有结果 → 展示 AI 套。
AI 没有套 → 空白，不再用本地三套顶上。

二、三块规则怎么咬合

适用性规则

哪些衣服能留下

冷热硬门槛、硬性需求（颜色/厚薄）、排除品类、核心不能丢、必须是你的衣橱 ID。没指定核心就不造核心。

用在：送给 AI 之前的候选衣橱，以及 AI 出套后的后核。

AI 组套

怎么配、怎么写理由

审美组合和措辞交给通义千问文本模型。本地几乎不改它选的品类搭配。

用在：筛完候选衣橱之后、后核之前。没有结果就空白。

组套规则

怎么配成三套

本地 A/B/C 组套已废除。网页旧模式仍可能走互补品类，小程序不再用。

用在：小程序不使用。

三、还可能像的地方

现在这样处理

① 默认核心已废除，三套不必共用一件。
② 后核仍只按衣服 ID 去重：两条不同的黑裙子仍算两套。
③ AI 失败不再用本地三套顶上。
