AI 穿搭筛选逻辑

小程序现行代码路线 · 2026-08-22 · 已按废除库存状态修订 · 红色块是设计写了、代码没做的步骤

准备 设计有、代码跳过 AI 组套 后核 本地组套（仅兜底） 给你看的结果

一、整条路线

1. 你点「生成搭配」

输入一句话（例如明天上班穿什么）+ 天气（自动定位 / 手动城市 / 这次没温度）。不管雨、风、湿度。

2. 只拿你这个微信号的衣橱

按登录用户隔离。衣橱是空的 → 直接 0 套，结束。衣橱里的衣服都能进名单，不再区分待洗、收纳。

3. 定核心衣服

你从某件点「围绕这件」→ 核心就是那件。
没指定 → 最新一件。三套都得带着它。

4. 设计要先筛冷热 · 代码现在跳过

设计：最高温 > 25℃ 丢掉非核心的冬寒/厚款/加厚；最低温 ≤ 10℃ 丢掉非核心的夏热/极薄；核心不丢。
代码：这一步没做，全部衣服都发给 AI。

5. AI 组套并写理由

模型只能用你衣橱里的真实 ID。提示要求：必须带核心、最多 3 套、整套 ID 不能完全重复。品类合不合理、好不好看，主要靠模型自己发挥。

AI 交回来之后分两条路

6a. AI 至少交回 1 套 → 后核

  1. 假 ID / 别人的衣服 → 丢掉
  2. 同一套里同一件出现两次 → 留一次
  3. 没有核心 → 强制加回去
  4. 这时才拦非核心冷热
  5. 整套 ID 完全相同 → 只留一套
  6. 最多留 3 套
  7. 补温度提醒、同色/撞色那句话（不再补待洗/收纳提醒）

不核：两条裙子能不能配、三套像不像、理由乱不乱。

6b. AI 失败或 0 套 → 本地组套

  1. 三套都带同一件核心
  2. 按互补品类每类最多 1 件（连衣裙只补鞋/外套/包/配饰）
  3. 候选先过冷热硬门槛
  4. 和核心同组标签命中 +1，你的话命中标签再 +1
  5. 方案 A/B/C 拿该品类第 1/2/3 名（标题不参与打分）
  6. 套模板理由，再补温度提醒和颜色关系

7. 给你看

6a 有结果 → 只展示 AI 套，本地组套算过也不给你看。
6a 空了 → 才展示 6b 的三套。

二、三块规则怎么咬合

适用性规则

哪些衣服能留下

冷热硬门槛、核心不能丢、必须是你的衣橱 ID、衣橱里的衣服都能留下、你说的冷热优先于温度。

用在：本地组套挑候选时、AI 出套后的后核。

AI 组套

怎么配、怎么写理由

审美组合和措辞交给通义千问文本模型。本地几乎不改它选的品类搭配。

用在：前筛被跳过之后、后核之前。有结果就盖掉组套路。

组套规则

怎么配成三套

互补品类、每类 1 件、打分、A/B/C 换件。不会配两条连衣裙。

用在：只当 AI 不可用时的成品。AI 成功时不算给你看。

三、你这次为什么三套很像

路线上的三个缺口叠在一起

① 没先筛，AI 看见全部衣服。
② 默认核心锁死为最新那件黑连衣裙，三套都得带它。
③ 后核不看品类，第 3 套可以是两条黑裙子；差异只按「整套 ID 是不是完全一样」算。

细则仍以 Excel《现行穿搭规则一览》四张表为准。本图只画关系和走哪条路，不替代逐条规则。待洗、收纳、可穿等库存状态已废除，不再当标签，也不再当筛选门槛。
