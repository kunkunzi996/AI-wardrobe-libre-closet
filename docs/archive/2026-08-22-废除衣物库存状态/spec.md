# 废除衣物库存状态 SPEC

- 阶段：P2
- 最后更新：2026-08-22
- 依据：用户已确认的 Q2A / Q3A+B / Q4A+B / Q5A；ADR 0005、0006；P6 用户确认启用

## 1 为什么做

### 用户问题

小程序不做待洗、收纳、清洁、需修补、已归档。衣服在衣橱里就是能穿。网页不再作为使用入口。

### 第一版希望带来的结果

用户在小程序里看不到、也用不到库存状态。备份和库存 Excel 不再写出状态。生产旧数据全部视为可穿。

## 2 MVP 范围

### 做

1. 小程序衣橱/搭配 JSON 去掉 `status`、`statusLabel`；`ready` 去掉 `wearableCount`。
2. 发给 AI 的衣物不含库存状态。
3. 网页衣橱去掉状态下拉、筛选和展示。
4. 备份 zip 不写 status，导入忽略；管理员 Excel 去掉「状态」列。
5. 数据库 `status` 列保留；旧行改为可穿。

### 不做

- 不拆除整个网页应用。
- 不 drop `garment.status` 列。
- 本轮不上传新体验版。

## 3 验收标准

1. 小程序衣物详情、搭配结果看不到待洗/收纳/可穿状态文案。
2. 衣橱列表、`recommend` 响应不含 `status`、`statusLabel`；`ready` 不含 `wearableCount`（页面未调用 ready 时以实际请求的接口为准）。
3. 备份 `manifest.json` 衣物对象不含 `status`。
4. 管理员库存 Excel 表头没有「状态」。
5. 沙盒衣橱件数和照片还在。

## 4 异常情况

1. 生产 UPDATE 不得改照片、不得删衣物。
2. 不得清空真实衣橱。
3. 不得拆除整个网页应用。

## 5 硬约束

1. 现在是基于小程序原生开发的，网页版是不会再使用了。
2. 衣服在衣橱里就是能拿来穿，不区分可穿、待洗、收纳、清洁、需修补、已归档。
3. 数据库 `status` 列先保留，本轮不 drop 列。

## 6 未决与风险

### 未决

- 体验版是否上传（当前仍 `1.0.1`）。

### 风险

- 开发者工具网络面板会混入部署前的旧请求，验接口须看部署之后的响应。
