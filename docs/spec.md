# 小程序结构化标签穿搭推荐 SPEC

- 阶段：P2
- 最后更新：2026-08-12
- 依据：2026-08-12 已确认的产品讨论、领域词汇与架构边界

## 1 为什么做

### 用户问题

现有小程序虽然已经为衣物建立了更完整的结构化标签，但生成穿搭时仍主要依赖品类、颜色、季节、风格和场合等旧信息。用户提出炎热通勤、低温保暖或围绕某件衣物搭配等需求时，新标签和真实温度没有稳定参与判断，可能推荐明显不合时宜的衣物，也无法清楚解释选择依据。

### 第一版希望带来的结果

用户在小程序生成穿搭时，系统先排除与明确冷热情境直接冲突的非核心衣物，再综合用户需求、有效搭配标签和色彩关系给出最多三套有实际差异的方案。用户能看见本次采用的城市与温度依据、衣物状态提醒以及简明的搭配理由；定位或天气不可用时仍能继续获得推荐。

## 2 MVP 范围

### 做

1. 小程序穿搭推荐使用有效搭配标签：同组优先采用新的结构化标签，缺失时才使用历史字段；各标签组等权且每组最多计算一次，排除穿着体验和被误写成版型的体验词。
2. 用户首次生成时可授权自动识别城市，也可手动选择城市；页面展示城市、当前温度和未来八小时温度趋势，并记住当前设备上最后选择的城市模式。
3. 根据未来八小时温度处理明确冷热冲突，同时保留用户明确需求和核心衣物的优先权，并向用户说明冲突或选择依据。
4. 一次返回零至三套有实际差异的完整或部分方案；允许所有库存状态的衣物参与，推荐非可穿状态衣物时显示状态提醒，没有指定核心衣物时优先选择最新的可穿衣物。
5. 定位被拒绝或天气数据不可用时继续根据用户输入和衣物标签生成，并明确提示本次没有使用实时温度。

### 不做

- 不修改网页端衣橱搜索。
- 不根据降雨、风力或湿度判断穿搭。
- 不支持指定未来日期生成穿搭。
- 不建立长期用户穿衣偏好模型。
- 不同时接入多个天气数据来源。
- 不在本功能中执行剩余衣物的生产补标。
- 不扩展为公开或商业运营版本。

## 3 验收标准

1. 已登录用户首次在小程序生成穿搭并同意定位后，能看到本次采用的城市、当前温度和未来八小时温度趋势，并获得基于用户需求和有效搭配标签生成的方案及大白话理由。
2. 已登录用户在未来八小时最高温为 25.0℃ 时生成穿搭，不会仅因该温度触发高温排除；最高温为 25.1℃ 时，明确标记为冬寒、厚款或加厚的非核心衣物不会进入方案；最低温不高于 10℃ 时，明确标记为夏热或极薄的非核心衣物不会进入方案。
3. 已登录用户明确要求保暖或指定一件与实时温度冲突的核心衣物时生成穿搭，仍能看到符合明确需求且保留核心衣物的方案，同时看到真实温度带来的注意事项。
4. 已登录用户拒绝定位，或天气数据超时、失败时继续生成穿搭，仍能看到零至三套符合现有衣橱信息的方案，并看到本次未使用实时温度的提示。
5. 已登录用户使用包含新旧标签及不同库存状态衣物的衣橱生成穿搭时，能看到新标签优先、旧字段兜底且同组不重复加权的结果；非可穿状态衣物带有状态提醒，方案不为凑满三套而重复，缺少合适单品时允许说明缺项并返回部分方案。

## 4 异常情况

1. 用户的原始精确位置不得被长期保存、复用于无关目的或泄露给无关方；定位只服务于本次城市温度判断。
2. 天气数据来源的访问凭据不得暴露给小程序用户或进入可公开获取的内容。
3. 任一用户的穿搭方案不得混入其他用户的衣物、标签或位置依据。

## 5 硬约束

1. 第一版只改变微信小程序穿搭推荐的用户体验，网页端衣橱搜索保持原样。
2. 未来八小时最高温严格大于 25℃ 才触发高温排除；最低温不高于 10℃ 才触发低温排除；缺少相关标签时不得推断为冲突。
3. 用户明确表达的需求高于实时温度；用户指定的核心衣物不得因温度冲突被替换，只能增加注意事项。
4. 新结构化标签按组优先，旧字段仅在同组新标签缺失时兜底；每组权重相同且最多计算一次；穿着体验不参与推荐，色彩关系按整套衣物动态判断。
5. 所有库存状态的衣物都可参与推荐；非可穿状态必须提示，默认核心衣物优先选择最新的可穿衣物，没有可穿衣物时才选择其他状态的最新衣物。
6. 用户未授权定位或温度不可用时不得阻止生成、静默猜测城市或使用默认城市；手动城市只保存在当前设备，并允许切回自动定位。
7. 一次最多返回三套有实际差异的方案，允许少于三套和部分方案；不得用明显不合适的衣物强行补齐。
8. 新版推荐对目标账号正式启用前，必须完成剩余十一件衣物的 AI 分析和补标时间记录，并完成人工数据核对；不要求每件衣物的所有标签组都有值。

## 6 未决与风险

### 未决

- 无会改变第一版产品行为的未决项。

### 风险

- 25.1℃即进入高温情境是较积极的产品门槛，真实使用中可能需要根据反馈调整，但第一版必须按当前门槛验收。
- 历史衣物的新旧标签可能缺失、冲突或包含旧体验词；兼容处理不当会造成重复加权或错误排除。
- 用户拒绝定位、设备定位不准或天气数据暂时不可用时，推荐质量会下降，但不能影响基本生成功能。
- 天气数据服务的配额、授权或使用政策未来可能变化；若产品从个人家庭使用扩展为公开或商业运营，必须重新评估合规边界。
